## 加载和复用

- 进入升级或商店时预热当前选项所需图集，不在启动阶段解码全部技能图片。
- 一份图集共享一个加载Promise、一张GPU纹理、一个材质和一组实例缓冲；并发请求去重，失败清除请求缓存以支持重试。
- 用户确认技能/购买时，所需图集未就绪则进入“准备技能”状态，停止模拟时间、移动与攻击；完成后才确认原操作。商店仍按原版本凭据验证，加载取消不扣金币或消耗升级选择。
- 宝箱自动奖励也检查新获得的技能依赖，避免绕过升级界面的资源门禁。
- 准备失败可重试。升级/商店来源取消后回到原界面；自动奖励已改变构筑时取消准备会返回营地，不带着缺图技能恢复战斗。
- 切后台、窗口变竖屏或音频中断时，准备完成也不自动恢复战斗；退出/重开使旧的异步确认失效。
- 重开清空原战斗对象池中的技能状态，已解码的三个图集保留复用，缓存数量固定。运行时只读诊断增加`skillResources`及`skillEffects`，不提供改数值接口。

## 渲染边界

`src/skill-vfx.ts`统一绘制冰环、绽放、绯梦弹与梦印。每种图集对应一个`InstancedMesh`，帧UV和淡出透明度使用实例属性；容量沿用原冰环2、梦系事件64、投射物24。纹理、材质和几何不随每次施法创建。

冰环空心与边缘遮罩、梦系边缘柔化和中心透明度沿用原表现规则；绽放按`event.age / event.duration`选择8帧。绯梦弹以原10 FPS循环，朝向随速度，原先的通用球体不重复叠加。伤害、Boss/精英系数、叠印与三层触发均继续由`src/core/`决定。

下一步可在用户确认实际效果后，继续迁移更多子弹、拖尾和命中特效；默认仍仅执行`npm run verify`，不自动运行模拟器。
