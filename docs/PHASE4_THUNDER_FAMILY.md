# 第四阶段 · 第二批：雷芽连锁

日期：2026-10-26。对应 plan.md 的 P3。状态：开发已接入；按用户要求未运行测试、类型检查、构建、浏览器、模拟器或真机验证。第四阶段仍在进行。

## 本批开放

新增正式支持 ID：`thunder-bud-weapon`（雷芽连锁）。正式支持名单由 19 项增加至 20 项；获取、升级、三武器槽、商店购买和宝箱授予继续走原 `Progression` / `RunBuild` 路径。本批不开放额外雷系独立弹幕、遗物、融合或新角色。

| 表现阶段 | 数据来源 | 接入行为 |
|---|---|---|
| 首次蓄电 | `ThunderWeapon.casts` 的 active、age、x/z、hops | 在原施法点显示黄色蓄电星核、短环与碎光；原 0.12 秒蓄电计时不变。 |
| 连锁放电 | `ThunderWeapon.links` 的实际 x/z、tx/tz、age、variant | 每条已生成的连锁使用八段折线连接真实端点，按原 0.26 秒寿命渐隐。 |
| 跳跃间隔 | 原 cast 的 nextAt、age、hops 和当前 x/z | 在实际链路来源点显示短促节点充电，不在渲染端选取下一个目标。 |
| 命中/消散 | `ThunderWeapon.impacts` 的 active、age、x/z、enemyId | 实际命中星光和碎屑按原 0.34 秒寿命淡出，位置跟随原事件池的更新。 |

首个目标可能在实际放电前失效或被替换，因此蓄力只标记施法点，不用 initialId 在渲染端绘制假定命中线。后续电弧只读已经产生的 links，不根据邻近敌人推测跳跃或伤害。

## 原规则边界

伤害、原 0.09 秒跳跃间隔、目标上限成长、衰减、障碍/出生保护过滤、同次不重复命中和攻击冷却继续由 `src/core/thunder-weapon.ts` 与原 Combat 调用决定。本批仅将该模块原有两处表现寿命提取为 `THUNDER_LIMITS.linkDuration` / `impactDuration`，数值保持 0.26 / 0.34，供清理和绘制共同使用。

没有添加渲染命中判断、额外伤害、控制效果或随机调用。武器说明和升级文案仍来自原 progression，未新增一套规则说明计算。

## 文件与接入

- `src/content/thunder-recipes.ts`：声明雷电色彩、线宽、折线段数、装饰偏移和 full/reduced 参数，只负责表现。
- `src/render/vfx/lightning-batch.ts`：固定折线缓冲，内部复用 PixelBatch；小接口 begin/put/finish。每条链路两端保持原坐标，内部折线只是装饰，不表示新的碰撞形状。
- `src/thunder-vfx.ts`：转换原施法、links 和 impacts 三个池，复用 AreaBatch 绘制小型蓄电环，复用 PixelBatch 绘制星核与碎屑。
- `src/content/enabled.ts` / `effect-recipes.ts`：登记雷芽稳定 ID、原武器来源及无需下载图集的雷电表现配方，接入统一奖励支持与资源准备路径。
- `src/view.ts`：创建、绘制、重开清理和同步细节档；低细节档不影响模拟。
- `src/main.ts` / `model.ts`：增加只读 `thunderEffects` 和 `skillEffects.thunder` 诊断，不开放改数值入口。

## 容量、低细节和生命周期

| 项目 | 上限 |
|---|---:|
| 原并行施法 | 4 |
| 原放电链路 | 32 |
| 原命中事件 | 32 |
| 必要电弧段 | 256（32×8） |
| 装饰电弧段 | 256，reduced 时绘制数量为 0 |
| 蓄电/命中星核与碎屑 | 136 |
| 蓄电短环 | 4 |

full/reduced 使用同一批实际 links、相同端点和相同八段必要电弧；reduced 只去掉外围光晕，并将每次命中的碎屑从三片减为一片，保留命中星核与蓄电标记。必要链路与装饰分开容量，不因装饰拥挤删除已发生的连锁。敌方危险预警仍使用更高绘制顺序。

全部纹理/材质/几何与实例缓冲在视图初始化时复用，不按每次施法或每跳创建。效果年龄来自原模拟状态，暂停、升级和资源准备不推进；原 reset/clear 清空事件，视图 reset 清空实例计数。没有额外计时器或异步动画回调。
