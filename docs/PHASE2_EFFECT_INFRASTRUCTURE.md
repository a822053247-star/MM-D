日期：2026-10-26。状态：开发已接入，未执行类型检查、构建、测试、浏览器、模拟器或真机验证。按用户要求继续以开发为主；“已接入”不代表阶段运行验收通过。

## 本批实现

| 模块 | 职责及接入 |
|---|---|
| `src/content/enabled.ts` | 保持原有 14 项正式奖励资格，声明稳定 ID、名称、武器来源和特效配方；分别记录代码、规则、表现、资源与用户验收状态。派生正式支持名单、构筑依赖和发布图集列表。 |
| `src/content/effect-recipes.ts` | 汇合已有两份生成图集元数据，明确四张启用图集的资源来源、绘制家族和必要表现；不手改生成文件。 |
| `src/assets/effect-assets.ts` | 统一 Promise 去重、图片解码、共享纹理创建及显式上传、失败重试、引用和 LRU 缓存。这里只有抖音本地首局分包路径。 |
| `src/render/vfx/atlas-batch.ts` | 从 SkillVfx 提取实例 UV、透明度、遮罩、矩阵和 Shader。借用纹理，拥有自己的材质、几何及固定实例缓冲。 |
| `src/render/vfx/sector-wave.ts` | 从 CampaignView 提取火焰扇形几何、帧选择和 Shader。帧 UV 写入几何，不再修改共享纹理 repeat/offset。 |
| `src/game/content-preparation.ts` | 统一升级、商店和已授予宝箱内容的确认门禁、重试、取消、失效版本和中断标记。资源模块不授予奖励或切换游戏模式。 |

`GameView` 创建唯一 EffectAssets 并传给两种特效视图。火焰启动加载也经过该模块；`SkillVfx` 不再加载图片或创建纹理，只将现有对象池状态转换为批次绘制参数。

## 资源和生命周期约定

- `prepare(contentIds)` 只准备资源，不增加长期引用。同一图集并发请求共用 Promise 和 Texture；梦弹与回响继续共享梦系绽放纹理。
- `setReferences(owner, contentIds)` 替换该 owner 的依赖集合，重复调用不累加引用。当前 owner 为 startup、build、confirmation。
- 当前构筑和待确认操作持有长期引用，所有准备请求持有临时引用直到全部依赖成功或失败。取消/重开解除旧确认引用，迟到的请求可以进入缓存，不能再次确认旧操作。
- `release(contentIds)` 仅释放无引用且无准备任务的图集，同时使 ready 失效；超出 16 MiB 内部目标时自动按最近使用顺序回收无引用缓存。活跃内容保留，不能为了预算删除仍会命中的攻击表现；若仅活跃内容就超预算，inspect 明确报告 overBudget。
- downloaded 表示本地首局分包下载成功；decoded 表示图片加载回调完成且尺寸吻合；drawable 表示纹理经过 renderer.initTexture 的显式准备。它不是 Shader 编译、整帧画质或设备性能验收。
- 上下文丢失使 drawable 全部失效；恢复后复用已解码图片重新准备。用户继续战斗时仍经过门禁。后台/音频中断期间异步完成不自动恢复战斗。
- 素材错误仍通过“准备技能”界面重试或取消；升级和商店取消回原界面，宝箱已授予内容的取消返回营地。

## 战斗边界

`main.ts` 在每帧和每个固定模拟步开始前检查当前构筑资源。`FirstRun.step` 增加可选 beforeCombat 钩子，位于波次边界处理之后、移动和攻击模拟之前，覆盖边界处理可能授予新内容的情况。未传入钩子的原模型调用保持原路径；没有改动 src/core 的伤害、奖励或随机规则。

绘制保持现有帧序、时序、尺寸关系、冰环空心遮罩、梦系透明叠加、梦弹朝向和实例容量。火焰继续使用 25/45/160 ms 三帧和原扇形映射。实际画面保持情况待后续体验确认。

## 发布与新增内容入口

`scripts/build.mjs` 从 RELEASE_EFFECT_ATLASES 获取去重后的发布图集，统一复制和校验哈希/100,000 字节限制；复制基础首局资源时排除旧 vfx 目录，避免绕过内容名单。构建代码已修改，本批没有执行。

共享内容配置供 Node 构建脚本直接读取，内部使用显式 `.ts` 导入；tsconfig 在原 noEmit 模式下启用 allowImportingTsExtensions，运行打包仍交给现有 Vite 流程。

以后新增内容依次处理：

1. 在原 core 规则中确认 ID、资格和池容量，不在渲染端复制伤害计算。
2. 用已有离线流程制作/登记运行图集，保留原图与生成清单。
3. 在 effect-recipes 声明资源来源和表现配方，在 enabled 登记武器来源或技能 ID。
4. 接入实际绘制并补齐说明后，才能标记规则/表现/资源完成，从而进入正式奖励池；用户验收独立记录。
5. 升级、商店、宝箱和构筑资源准备继续使用同一门禁和引用管理。

本批没有新增 PNG 或改动现有图集，因此四图集源文件增量为 0；仍合计 135,615 字节。主包 JS、主包总量和首局总量变化未测量，旧 size-report.json 保留历史结果，不宣称重构已经减包或预算通过。
