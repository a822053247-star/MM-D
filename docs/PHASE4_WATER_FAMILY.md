# 第四阶段 · 第一批：水系家族

日期：2026-10-26。对应 plan.md 的 P3，本阶段按家族分批；本次只开发水系，不代表整个第四阶段已完成。状态：代码已接入，未运行测试、类型检查、构建、浏览器、模拟器或真机验证。

## 已开放的内容

| ID | 内容 | 本批表现与原规则接入 |
|---|---|---|
| `bubble-weapon` | 水泡弹 | 空心水泡轮廓、亮点、实际轨迹、水滴接触反馈与消散；沿用原自动索敌、伤害、武器等级、三槽限制和减速。 |
| `azure-burst` | 苍蓝震爆 | 显示原落点、全范围轮廓与聚光；以原 `detonated` 状态切换震爆和淡出，原规则在聚光后结算一次圆内伤害。 |
| `star-tide` | 星潮脉冲 | 逐圈读取 `cast.waves[i].radius` 绘制实际波前；使用原环带宽度，保留原多圈成长和每圈命中账本。 |
| `still-sea` | 静海法阵 | 固定领域、实际半径、淡色铺底和水滴标记；沿用原跳伤、减速、持续时间及同类重叠约束。 |
| `returning-ring` | 回流水环 | 随原施法状态位置移动的范围填充和外沿，保留圆内持续伤害与减速；没有护盾或无敌判定。 |

正式奖励支持项由 14 项增加到 19 项，只新增上述五项；升级、商店和宝箱继续通过原 `Progression` 资格与授予路径。四个独立技能是否需要水泡武器，仍以原规则为准，本批不额外添加先决条件。练习模式没有扩大奖励池，正式模式仍由焰绒使用火焰横扫起手。

## 实现文件

- `src/core/projectile-presentation.ts` / `content/projectile-recipes.ts`：水泡接入上一批的真实接触、撞墙、消散、轨迹和显示参数。带融合 ID、配对或自定义表现的弹体仍走旧兼容路径。
- `src/render/vfx/pixel-batch.ts`：新增空心水泡和水滴轮廓，复用同一固定缓冲和 Shader，无逐弹纹理创建。
- `src/render/vfx/area-batch.ts`：共享圆盘/圆环实例绘制。外半径、内半径来自表现调用参数，能分别表达圆形伤害范围与实际水环前沿，不把所有水系技能画成同一个扩张圆。
- `src/content/water-recipes.ts`：仅保存色彩、铺底透明度、高度和装饰档位参数，不包含伤害或资格公式。
- `src/water-vfx.ts`：从原 `WaterAoe.casts` 和敌人状态读取范围、落点、计时与状态，只负责绘制。
- `src/core/water-aoe.ts`：在原伤害调用后记录有界接触表现，增加 64 槽水滴事件池。原命中循环、伤害、控制、目标选择和升级计算不变；池满替换最旧表现，不跳过伤害。
- `src/content/enabled.ts` / `effect-recipes.ts`：登记五个完成基本表现的 ID、必要表现和零下载资源依赖，接入统一正式名单和资源门禁。
- `src/view.ts` / `main.ts` / `model.ts`：接入水系视图、细节档、重开清理和只读 `waterEffects` / `skillEffects.water` 诊断。
- `src/campaign-view.ts`：敌方危险圆与冲刺线使用更高绘制顺序，避免友方水系铺底覆盖预警。

## 状态、质量和容量

湿润水滴读取 `enemy.wetTime`，减速地面短纹读取 `slowTime`，冻结晶片和敌人冰色读取 `freezeTime`。不会通过附近水系图形反推状态，也不会因为画面缺失而延长控制。现有冰环与水系产生的冻结组合继续使用原规则；其他霜晶武器尚未开放。

满细节与低细节共用相同的水泡主体、技能范围、实际波数和状态标记。低细节仅减少水滴碎片、边缘装饰与内层装饰涟漪，保留危险预警。

运行期固定分配 32 个范围实例、256 个水滴/装饰实例、768 个状态实例；施法池沿用原 2 次震爆、2 次脉冲、2 个法阵、1 个随身水环及最多三圈。新水系接触事件池为 64 槽。没有按施法或命中创建纹理、材质或几何。

表现年龄由原模拟步推进；暂停、升级、商店和准备资源时不推进。水系事件在原 clear/reset 路径清空，视图重开清空批次计数；旧领域和水滴不会跨局保留。
